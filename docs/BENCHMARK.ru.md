# SvinDB и Elasticsearch: измеренное сравнение

**Статус этих чисел.** SvinDB — ранний прототип. Это одна машина, один синтетический корпус и 3 прогон(ов) одного и того же теста; цифры показывают, где прототип находится сегодня, и не являются общим приговором ни одному из движков.

## Условия

|  |  |
|---|---|
| Машина | macOS-26.3.1-arm64-arm-64bit, 10 CPU, 16 ГиБ ОЗУ |
| SvinDB | 3.0.0-alpha.3, релизная сборка, настройки по умолчанию, `SVINDB_DISK_FLOOR_MB=1` (см. примечания) |
| Elasticsearch | 9.2.3, нативная сборка для macOS, 1 узел, куча 4 ГиБ (фиксированная), 1 шард, 0 реплик, `refresh_interval=-1` на время загрузки, дисковые пороги выключены (см. примечания) |
| Корпус | 1 000 000 синтетических документов, 386 МБ NDJSON (title, body, keyword-категория и автор, long, double, date); одни и те же байты отправляются обоим движкам через `_bulk` Elasticsearch |
| Клиент | стандартная библиотека Python, одно постоянное соединение на поток клиента, загрузка в 4 потока(ов) пачками по 5000 документов |
| Прогоны | 3 (показана медиана; наибольший разброс любого p50 между прогонами: 41%; разница внутри разброса названа «примерно одинаково») |
| Фоновая нагрузка | средняя загрузка за минуту в начале каждого прогона: 3,2, 5,9, 6,4. На машине также работала посторонняя нагрузка, примерно одно занятое ядро |

## Проверка корректности

Число скорости имеет смысл читать только рядом с доказательством, что оба движка отвечают на один и тот же вопрос. Для каждого семейства запросов сравнивалось точное число совпадений, а для агрегаций — суммы, минимум, максимум и корзины на нескольких вариантах запроса. Сравнение, в котором обе стороны вернули ноль, отвергается.

**14 из 14 семейств запросов вернули одинаковый результат** (`term / rare`, `term / medium`, `term / frequent`, `OR of two terms`, `AND frequent + medium`, `AND frequent + frequent`, `phrase (two words)`, `term + range filter`, `term, sort by views`, `range count (size 0)`, `terms agg on category`, `stats agg, all docs`, `terms agg, high cardinality`, `date histogram (month)`).

Списки топ-10 по релевантности не обязаны совпадать, потому что варианты BM25 различаются; среднее пересечение первых десяти id — 96%.

## Как это читать и чего это не показывает

- **Память посчитана двумя способами намеренно.** Физический объём — память, принадлежащая процессу (куча и анонимные страницы). Резидентная память включает ещё и отображённые файлы индекса. SvinDB читает индекс через `mmap`, поэтому его рабочий набор лежит в страничном кеше операционной системы и в его физическом объёме почти не виден; для него честнее резидентная память. У Elasticsearch фиксированная куча 4 ГиБ, которую выбрал я, и меньшая куча уменьшила бы его объём.
- **Только прогретый кеш.** macOS не умеет сбрасывать страничный кеш без прав администратора, поэтому числа получены на тёплом кеше. Строка про перезапуск перезапускает процесс, а не кеш диска.
- **Оба предохранителя отключены.** На машине мало свободного диска, и оба движка по умолчанию отказываются писать в таком состоянии (`SVINDB_DISK_FLOOR_MB` у SvinDB, `cluster.routing.allocation.disk.threshold_enabled` у Elasticsearch). Для теста оба ослаблены.
- **Это не боевые настройки ни одного из движков.** Elasticsearch — один шард без реплик и с приостановленным refresh на время загрузки; SvinDB — настройки по умолчанию. Умолчания долговечности сохранены с обеих сторон (подтверждённые записи сброшены на диск).
- **Синтетический корпус, одна машина, один фоновый процесс.** Текст порождён из словаря на 30 000 слов с распределением Ципфа: частоты терминов правдоподобны по форме, но язык — нет. На машине также работала посторонняя фоновая нагрузка, примерно одно занятое ядро.
- **Загрузка у SvinDB шла через совместимый с Elasticsearch маршрут `_bulk`**, который преобразует каждый документ. Это путь, которым пойдут переносимые клиенты, но собственный формат пачек SvinDB не измерялся.

## Как повторить

```bash
cargo build --release --locked -p svindb-server
python3 -I tools/bench_vs_es.py --docs 1000000 \
  --svindb target/release/svindb --es-home /path/to/elasticsearch-9.2.3 \
  --workdir /path/to/scratch --output run1.json
python3 tools/bench_vs_es_report.py --lang ru run1.json run2.json run3.json > docs/BENCHMARK.ru.md
```

Скрипт сам запускает оба сервера, ему нужно примерно 3 ГиБ свободного места, и он пишет все сырые числа в JSON-файл.
